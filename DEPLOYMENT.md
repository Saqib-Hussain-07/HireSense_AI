# HireSense AI — Deployment Guide

A step-by-step reference for deploying HireSense AI to different environments.

## Option 1 — Local Development (no Docker)

> Fastest way to start coding.

```bash
# 1. Clone the repository
git clone <repo-url> hiresense-ai
cd hiresense-ai

# 2. Install all dependencies (root + workspaces)
npm install

# 3. Configure environment
cp backend/.env.example backend/.env
# Edit backend/.env with your actual keys

# 4. Start both services with hot-reload
npm run dev
# Backend: http://localhost:5000
# Frontend: http://localhost:5173

# 5. Verify API keys
npm run check:apis
```

## Option 2 — Docker (Local / VPS)

> Fully containerized — MongoDB included.

### Development (hot-reload)

```bash
# Start everything
docker compose up --build

# Stop everything
docker compose down

# Stop and remove volumes (wipes MongoDB data)
docker compose down -v
```

Services:
| Service | URL |
|---|---|
| Frontend (Vite) | http://localhost:5173 |
| Backend API | http://localhost:5000 |
| MongoDB | mongodb://localhost:27017 |

### Production

```bash
# 1. Copy and configure secrets
cp backend/.env.example backend/.env
# Edit backend/.env

# 2. Set required env vars for production compose
export CLIENT_ORIGIN=https://yourdomain.com
export JWT_SECRET=$(openssl rand -hex 32)
export GEMINI_API_KEY=your_key
# ... set all other keys

# 3. Start production stack
docker compose -f docker-compose.prod.yml up --build -d

# 4. View logs
docker compose -f docker-compose.prod.yml logs -f

# 5. Tear down
docker compose -f docker-compose.prod.yml down
```

Frontend is served on **port 80** by nginx. Point your domain's A record to the server IP.

## Option 3 — Render.com (Recommended for free-tier hosting)

> One-click deployment via `render.yaml`.

### Setup

1. Push the repository to GitHub.
2. Go to [dashboard.render.com](https://dashboard.render.com) → **New → Blueprint**.
3. Connect your GitHub repo — Render auto-detects `render.yaml`.
4. Render creates three services automatically:
   - `hiresense-api` — Node.js Web Service
   - `hiresense-app` — Static Site (CDN-served React build)
   - `hiresense-mongo` — Managed MongoDB

### Required secrets (set in Render dashboard → Environment)

| Variable | Where to get it |
|---|---|
| `GEMINI_API_KEY` | [Google AI Studio](https://aistudio.google.com) |
| `GROQ_API_KEY` | [console.groq.com](https://console.groq.com) |
| `ELEVENLABS_API_KEY` | [elevenlabs.io](https://elevenlabs.io) |
| `ELEVENLABS_VOICE_ID` | ElevenLabs dashboard → Voices |
| `CLOUDINARY_CLOUD_NAME` | [cloudinary.com](https://cloudinary.com) |
| `CLOUDINARY_API_KEY` | Cloudinary dashboard |
| `CLOUDINARY_API_SECRET` | Cloudinary dashboard |
| `GOOGLE_CLIENT_ID` | Google Cloud Console → OAuth 2.0 |
| `WHISPER_API_KEY` | OpenAI or Groq key for Whisper STT |

> `JWT_SECRET` is auto-generated by Render (`generateValue: true`).
> `MONGO_URI` is auto-wired from the managed database.

### Free tier notes
- Backend sleeps after 15 minutes of inactivity (cold start ~30s).
- Upgrade to **Starter ($7/mo)** for always-on.
- MongoDB free tier: 256 MB storage — sufficient for development.

## Option 4 — Vercel (Frontend) + Render (Backend)

> Best for production: Vercel CDN for the React app, Render for the API.

### Frontend → Vercel

```bash
# Install Vercel CLI
npm i -g vercel

cd frontend
vercel

# Set build settings:
#   Framework Preset: Vite
#   Build command:    npm run build
#   Output dir:       dist
#   Environment var:  VITE_API_URL = https://hiresense-api.onrender.com
```

Create `frontend/vercel.json`:
```json
{
  "rewrites": [
    { "source": "/(.*)", "destination": "/index.html" }
  ]
}
```

### Backend → Render

1. In Render dashboard → **New Web Service**
2. Root directory: `backend`
3. Build command: `npm ci --omit=dev`
4. Start command: `node src/server.js`
5. Set all environment variables listed above.
6. Set `CLIENT_ORIGIN` to your Vercel frontend URL.

## Option 5 — Railway

> Simple: each folder is a separate Railway service.

```bash
# Install Railway CLI
npm install -g @railway/cli
railway login

# Deploy backend
cd backend
railway init
railway up

# Deploy frontend
cd ../frontend
railway init
railway up
```

Set environment variables in the Railway dashboard for each service.

## Environment Variables Reference

See [`backend/.env.example`](backend/.env.example) for the full list with documentation.

| Variable | Required | Default | Notes |
|---|---|---|---|
| `PORT` | No | `5000` | Render overrides with its own value |
| `NODE_ENV` | Yes | — | Set to `production` in deployments |
| `MONGO_URI` | Yes | — | MongoDB Atlas or managed DB URI |
| `JWT_SECRET` | Yes | — | Min 32 chars, random |
| `CLIENT_ORIGIN` | Yes | `*` | Your frontend URL (CORS) |
| `GEMINI_API_KEY` | Yes | — | Primary AI reasoning |
| `GROQ_API_KEY` | Yes | — | Fallback AI + Whisper STT |
| `ELEVENLABS_API_KEY` | No | — | TTS voice; browser SpeechSynthesis is fallback |
| `CLOUDINARY_*` | No | — | Resume storage; local `uploads/` is fallback |
